New in 1.3

The reactive engine, under a policy without unsafe-eval.

The default engine compiles each directive expression with new Function, so its pages need 'unsafe-eval'. faqir-core.csp.js is the same engine, the same directives, controllers and API, with one region swapped: expressions go through a tokenizer, a Pratt parser and a tree-walking evaluator. No string ever becomes code. This page runs on it.

Outside the subset, it says so

An unsupported construct fails like any expression error, naming it.

<div l-data="{ n: 1 }"
     l-text="(() => { switch (n) { case 1: return 'one' } })()">
</div>
// console: [Faqir] Expression error: … Unsupported syntax "switch"

The development twin, faqir-core.csp.dev.js, records it with the element's markup and says the strict-CSP subset is the reason.

The subset directive expressions use.

Taken from what the registry, this site and the docs actually write. Every expression in them parses, and a test keeps it that way.

SupportedNot supported
member, computed and optional access, calls, new, spread argumentsclasses, generators, async/await, import()
number, string, template and regex literals; arrays and objects with spread, shorthand, computed keys, methods and gettersdestructuring, default parameters, tagged templates, labels
every unary, binary and logical operator, ??, typeof, in, instanceof, the ternaryswitch, try/catch, throw, while, do, classic for (;;)
= and every compound assignment, ++ and --function declarations as statements
blocks, if/else, return, let/const/var, for…of, for…in, break, continue; arrow and function expressions

constructor, __proto__ and prototype are not reachable from an expression, which closes the classic reach from any value to Function. It is not a sandbox: an l-* value is still code, in either build. The interpreter weighs about 4.7 KB gzip more than the default engine, under a budget of its own.
