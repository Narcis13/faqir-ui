faqir-core

The whole engine is attributes on the markup you already wrote.

faqir-core is a zero-dependency reactive runtime with no build step and no template language, held under a gzip budget the release gate enforces. It reads l-* attributes off the DOM, evaluates plain JavaScript against the nearest scope, and updates only what changed. Components stay components: the engine drives them through the same five protocol attributes an agent already knows.

Loading it

One script tag, bound on DOMContentLoaded.

Add data-manual to bootstrap yourself with Faqir.start(). Anything injected after load — a fetched fragment, a cloned row — is inert until Faqir.initTree(el) walks it. 

<script src="core/faqir-core.js" defer></script>

Expressions are plain JavaScript evaluated against the nearest scope: any name the scope declares is in scope unqualified, and the $… magics below are always available.

The vocabulary

Every directive the engine implements.

Read out of the engine source at build time, so this table cannot describe a runtime other than the one this site ships.

l-init runs once, when the scope is ready; l-effect runs straight away and again whenever something it read changes. Together they reach outside the scope — the next example writes this browser tab's title, so type and watch the tab. l-cloak keeps the line it sits on hidden until the engine has bound it, so nobody sees it empty.

l-html writes markup rather than text. It is never sanitized, so bind only markup your own expression built — the development build reports every use. l-teleport moves an element to the first match of a CSS selector and keeps it bound to the scope that wrote it: the buttons below are written last, inside the stack, but render in the bar at the top, and still change step. Overlays use it with l-teleport="body" to escape a clipping ancestor.

Modifiers

Dotted suffixes, per directive.

A modifier is part of the attribute name, never a separate attribute. Times belong to the modifier they qualify — .debounce500ms, not .debounce.500ms, which is two modifiers and a discarded number.

l-model's modifiers decide what reaches the scope and when. .number stores a number, so the total below is a sum and not two strings glued together; .lazy waits for change, which fires when you leave the field; and @submit.prevent keeps the form on this page instead of navigating.

l-model.debounce holds the write until you stop typing for 300ms. The counter is a $watch on the bound key, so it counts the writes the scope actually received.

l-on's modifiers shape the event itself. Every click in the next example is traced: the root hears it first through .capture and again as it bubbles back; .self answers only when the panel itself is the target; .stop ends the trip at its button; and .once removes its own listener after the first click.

.window and .document move the listener off the element. .debounce and .throttle take their time inside the same modifier — resize the window (the width lands 300ms after you stop), scroll the page (at most one update per 100ms), press a key anywhere. The scroll listener sits on the document in the capture phase: scroll does not bubble, and this site scrolls inside its <main> rather than the window, so .capture is how a document listener hears it. It is also .passive, telling the browser it never calls preventDefault(), so scrolling never waits on it.

Magics

The bridge from an expression to the component.

$state, $variant and $ui are what make this engine a Faqir engine rather than a generic one: they read and write the protocol attributes of the nearest [data-ui], so a controller setting data-state="open" re-runs every expression that read it.

$el is the scope root, the callout here; $this is the element the expression is written on, so each button reads its own value. Assigning $variant writes the callout's data-variant, and the title, which reads it, follows.

$ui is the controller of the component a scope sits in — $ui.close() inside the popover — and, called with a selector, any other component's: the second button opens the popover with $ui('#engine-popover').open(). The popover's own scope reads $state, which its controller writes, so the trigger's label follows the popover however it opened or closed — by click, by Esc or by a click elsewhere. Its buttons report back with $dispatch, a bubbling event the outer scope reads through $event.detail.

$store holds every store registered with Faqir.store(), shared by every scope on the page. A page would normally register one from a script; this page carries no inline scripts, so the outer scope makes the same Faqir.store() call from its l-init, which runs before either card binds. Change the unit in one card and the other follows.

$nextTick runs after the DOM has caught up: the editor below only exists once l-if renders it, so focusing it has to wait a tick. $watch hands a callback the new and the old value — here it notices the moment the word count crosses the goal — and $id makes ids unique to this scope, for aria-describedby.

Server data

l-source binds a REST collection into the scope.

l-source:messages="/api/messages" injects messages, messagesLoading, messagesError and a $messages CRUD controller. The example below reads this site's own static endpoint, so what you see is a real request.

.lazy skips the first load, so nothing is fetched until you ask. .key.id names the property that identifies a row — the controller finds rows by it — and .optimistic applies a write to the list before the server answers, undoing it if the request fails. This site is a static host that only answers GET, so the DELETE behind Archive fails: the row leaves, comes straight back, and the error says why. Against a real API the row would stay gone.

.poll.15000 re-loads the collection every fifteen seconds. An l-effect on the root stamps the time whenever a load finishes, and the controller's stopPolling() and startPolling() pause and resume it.

Plugins

The official plugins, each one file.

A plugin adds directives and magics to the same expression language. Copy the file, load it after the engine, and the vocabulary is there. The table and the snippet under each plugin's name are read from the plugin's own source header; the live examples after them run on this page.

All of them, running

This page loads every plugin after the engine, so the examples below are live. l-collapse animates the list's height; l-persist saves open to localStorage, so the list is still open after a reload; and $persist() reads and writes one value by hand — here, a count of your visits.

l-intersect runs when its element enters the viewport, l-intersect.leave when it leaves, and l-intersect.once disconnects after its first match. Scroll this card off the screen and back.

One form, three plugins. l-validate paints each field-group's errors on submit and live after it, and its expression runs only when the form is clean. l-validate:available.async waits on a promise — this page has no server, so isFree() answers after 300ms from a short list (admin, faqir and root are taken). l-mask formats the phone number while l-model keeps the bare digits. l-rules applies a JSON rules definition — the same one a server would check — that shows and requires Company only for a team, asks a team for at least two seats, and computes the price — 5 a seat, or 8 for a team — which $rules reads back.

Inspecting a live page

window.__FAQIR_DEVTOOLS__, in both builds.

Both engine builds install the handle (version: 1). Use it when driving a browser to check what the engine actually bound: inspect(el|selector) for one element, scopes(within?) for the declared scope roots, components(within?) for every [data-ui] with its parts and controller, stores() for the registered stores, warnings() for recorded diagnostics, and dev, which is true only under the development build.

core/faqir-core.dev.js behaves identically and reports four diagnostic classes with the offending element's outerHTML: a failed expression, an l-… attribute nothing handles, an unkeyed l-for that reordered, and an l-html write. Develop against it; ship core/faqir-core.js. faqir dev also injects an inspector overlay — Ctrl + Shift + F — which is served by the dev server and never written into a project.
