Faqir UI

A UI framework an agent can write correctly on the first try. Five attributes (data-ui, data-part, data-state, data-variant, data-size), one manifest per component, zero runtime dependencies, and no build step in your project.

This site is the proof. It is built from registry components and design tokens only, its content is generated from component manifests, and every page it ships is held to faqir audit and axe in CI.

How it works

A component is a contract, not a class name. The contract lives in a manifest — anatomy, slots, variants, states, accessibility, and the design tokens it consumes — and the CSS targets those attributes. Read the manifest and you know the component; write the attributes and you have used it correctly. 

<button data-ui="button" data-variant="primary" data-size="md">Save</button>

No class names to memorise, no import graph to satisfy, nothing to compile. The same markup works in a static file, a template engine, React, or Vue.
