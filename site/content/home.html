The interface is the contract. Now it has a personality.

Faqir is a UI framework written for two readers at once. People get a component system that ships as plain HTML and CSS. Agents get manifests, an auditor that says yes or no with a line number, and a theme system described by fourteen measurable axes. Nothing is hidden in a build step.

What arrived in 1.1

The release is called Personality. Three things shipped: a theme system you can measure, a rules platform that gives one verdict everywhere, and a night shift that designs while nobody is watching.

Theme System 2.0

A theme used to be a colour palette. Now it is a voice: type roles, heading tone, silhouette, depth, material, motion and focus, each a token family a stylesheet re-declares. The fourteen axes are derived from the CSS, never declared by hand, so the gallery cannot lie about a theme. Twelve of the shipped themes were generated from a seed and pass the same distinctiveness gate as the authored ones. 

faqir theme generate candy \
  --accent "#ef5da8" --type rounded --shape pill \
  --depth soft --motion springy

Rules that travel

A form's validation is one JSON definition. The same evaluator runs it in the page through the l-rules plugin, in Node through @faqir-ui/rules, and on the command line through faqir rules lint. A schema-driven form emits its rules with its markup, so the browser and the server never disagree. 

{
  "fields": { "kind": { "type": "string" },
              "vat":  { "type": "string" } },
  "rules": [ { "id": "vat-required",
               "require": "vat",
               "when": { "==": [{ "var": "kind" }, "company"] } } ]
}

Night Shift

Every night a queue of briefs becomes theme candidates. Each one is generated, rendered, scored against a taste rubric it cannot argue with, and either lands as a pull-request-ready branch or is written to the ledger with the reason it was discarded. The morning digest is a page, not a log. 

bun run dream:nightly
# queue → dream → gate → ledger

bun run dream:digest
# the week, on one page

The loop an agent runs

Writing a page was never the hard part. Knowing it is right is. Faqir closes the loop with a contract to read, an auditor that answers, and a repairer that fixes what is safe to fix.

  1. Read the manifest

    Slots, variants, states, ARIA requirements and safe transforms, as JSON beside every component.

    faqir inspect dialog --json

  2. Write the markup

    Five attributes. No classes to invent, no build to run, no framework to choose first.

    <div data-ui="dialog" data-size="md">

  3. Audit it

    Every rule the auditor knows, run by one engine, with the same answer in the CLI, the MCP server and this site's playground.

    faqir audit page.html --json

  4. Repair what is safe

    Deterministic fixes for known mistakes. Anything needing judgement comes back as a finding with a line number.

    faqir repair page.html
